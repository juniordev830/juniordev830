## catalogo-municipios

[Repositório](https://github.com/juniordev830/catalogo-municipios) · [README](https://github.com/juniordev830/catalogo-municipios/blob/main/README.md) · blob `29e7fe0453ff`

### Propósito declarado
Ferramenta offline em PHP para consultar registros municipais com filtros, paginação, estatísticas, raio geográfico e exportação CSV/GeoJSON. Não consulta APIs, não modifica dados de origem e **não apresenta o conjunto de exemplo como base oficial do IBGE**.

### Detalhes técnicos documentados
**Estrutura do JSON**

O arquivo deve conter `fonte` (identificação textual), `atualizado_em` (data real em AAAA-MM-DD) e `municipios` (lista). Cada município precisa de `id` (inteiro positivo único), `nome` (texto) e `uf` (uma das 27 siglas brasileiras).

São opcionais: `populacao` (inteiro não negativo), `latitude` e `longitude` (sempre juntas), e `codigo_ibge` (string de sete dígitos). Valores ausentes permanecem `null`; o aplicativo não inventa dados. Dados reais devem trazer a fonte, a data de referência e condições de uso.

**Funcionalidades**

- Busca por nome sem diferenciar maiúsculas e acentos portugueses.
- Filtros por UF, população mínima e máxima.
- Ordenação por nome, UF, ID, população ou distância, com paginação estável.
- Busca em raio por fórmula de Haversine (distância aproximada em quilômetros), somente para registros com coordenadas.
- Estatísticas sobre cobertura de população, coordenadas e quantidades por UF.
- Exportação CSV com neutralização de células que poderiam ser interpretadas como fórmulas.
- Exportação GeoJSON com pontos na ordem correta longitude/latitude, omitindo registros sem coordenadas.

O exemplo usa IDs sintéticos e não representa uma base oficial. Não há consulta ao IBGE, SQLite ou cache conectado ainda. A busca ignora maiúsculas e os acentos comuns em português (por exemplo, `sao goncalo` encontra `São Gonçalo`).

A API PHP expõe `Municipios\Catalog::validate()`, `search()`, `statistics()`, `csv()` e `geojson()`.

**Testes e CI**

O GitHub Actions executa análise de sintaxe, os testes originais e 23 novos cenários. A suíte cobre validações, filtros, ordenação, distâncias, exportação, neutralização de fórmulas e a CLI.

**Limitações**

Não é uma base geográfica oficial, não faz geocodificação, não fornece fronteiras municipais e não implementa consulta por polígono. O cálculo de distância é aproximado e não representa distância rodoviária. O limite por consulta é 1000 registros, com no máximo 100000 registros carregados no catálogo. Não há dependência de serviços externos.

## cifras-transpositor

[Repositório](https://github.com/juniordev830/cifras-transpositor) · [README](https://github.com/juniordev830/cifras-transpositor/blob/main/README.md) · blob `df43c5974249`

### Propósito declarado
CLI em **Rust** para mudar o tom de linhas de cifras, incluindo acidentes, extensões e baixo invertido. Exemplo: `C#m7/G#` transposto dois semitons abaixo resulta em `Bm7/F#`.

### Detalhes técnicos documentados
**Executar**

Instale Rust com Cargo a partir de [rust-lang.org](https://www.rust-lang.org/tools/install). Não há dependências externas.



O resultado vai para a saída padrão. Para salvar, redirecione para **outro arquivo**, evitando substituir a entrada.

**Estrutura e validação**

`src/main.rs` contém o parser, a transformação pura e o adaptador de CLI. `examples/` traz conteúdo fictício/autoral. O workflow em `.github/workflows/ci.yml` compila, testa e executa o exemplo em Rust 1.85.

O ambiente de preparação não possui compilador Rust; a validação executável está a cargo do GitHub Actions. Consulte a execução do commit para conhecer seu resultado.

**Limites e próximos passos**

Esta versão aceita cifras latinas de A a G, acidentes simples e os sufixos descritos no parser. Acordes **entre colchetes** são transpostos dentro de linhas de letra, mantendo palavras e marcações inválidas, como `[Refrão]`, intactas. Em linhas mistas, somente os acordes entre colchetes são transpostos. Ainda não interpreta tablaturas, notação em graus ou cifras embutidas sem colchetes. Uma linha de letra formada somente por nomes de acordes também seria interpretada como cifras. O alinhamento conta caracteres em vez de bytes.

`nom`, `clap`, editor gráfico e importação de formatos são possibilidades futuras, ainda não instaladas. A arquitetura proposta anterior está em `ARQUITETURA.md` e descreve a evolução planejada.

## code-security-scanner

[Repositório](https://github.com/juniordev830/code-security-scanner) · [README](https://github.com/juniordev830/code-security-scanner/blob/main/README.md) · blob `0b0aedb0cf58`

### Propósito declarado
Analisador estático **somente leitura**, baseado em regras; procura construções que merecem revisão em Python/JavaScript/TypeScript. Emite JSON com arquivo, linha, severidade e regra.

### Detalhes técnicos documentados
**Como executar**

Use `--exclude` com nomes de pastas para ignorar diretórios adicionais em qualquer nível. O argumento pode ser repetido. Com `--fail-on medium`, achados médios e altos retornam código 1. O padrão continua sendo `high`, e `none` mantém código 0 para achados de regra; **uma varredura incompleta sempre retorna código 2**, independentemente desse parâmetro.

**Testes**

O GitHub Actions executa os testes automaticamente em pushes e pull requests.

**Segurança e limitações**

Regras simples geram falsos positivos e falsos negativos; nunca executa os arquivos. As regras `PY-EVAL` e `PY-SHELL` são aplicadas somente a Python, enquanto `WEB-INNERHTML` verifica JavaScript/TypeScript (inclusive JSX/TSX). Em arquivos Python com sintaxe válida, utiliza a AST para detectar chamadas (inclusive nas expressões de f-strings), evitando falsos positivos de atribuições e declarações. Quando não é possível analisar a sintaxe, usa um fallback lexical que mascara strings e comentários. Não executa o código analisado. Mantém a numeração das linhas. Não é uma análise de fluxo: aliases e chamadas dinâmicas ainda podem escapar, e arquivos com sintaxe inválida recebem apenas uma verificação heurística. Regras web continuam heurísticas.

A leitura de cada arquivo é limitada a 256 KB, inclusive quando o arquivo muda durante a leitura. Arquivos grandes, fontes ilegíveis, caminhos que não sejam arquivos regulares e diretórios que não possam ser percorridos geram o achado `SCAN-INCOMPLETE` e fazem a execução retornar código 2. Assim, uma pasta inacessível não é apresentada…

**Evolução planejada**

Integrar Semgrep e scanners de dependências, supressões justificadas e integração automática da saída SARIF já disponível com o GitHub Code Scanning.

Protótipo de investigação noir com regras testáveis em Python. Este repositório contém
